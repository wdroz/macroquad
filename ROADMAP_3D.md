Source of truth for the fork experiment and its unattended enhancement rounds. Make small 3D and 2D games easier to build with macroquad, including menus, HUDs and tools. Keep a thin, beginner-friendly API over the existing renderer and `glam`, with reusable engine features rather than game-specific behavior.

The filename stays `ROADMAP_3D.md` so existing prompts and automation keep working. Completed specifications, dated game pain points and the full round log through the AABB/capsule sweep are preserved in [roadmap history](docs/roadmap-history.md). The unchecked list under **Priorities** is the only implementation queue.

## Current state

- **Next scheduled round: enhancement — Character step offset**. The AABB character controller builds on the completed body sweeps; stair stepping and the remaining unchecked items below are proposals.
- **3D foundations already available:** collision primitives, contacts, sphere sliding, body sweeps against AABBs/OBBs/spheres/capsules, a kinematic AABB character controller, retained geometry, resource diagnostics, glTF materials/lighting, editable poses, morph instances and transform/weight clips. See the [3D guide](docs/3d-guide.md).
- **UI/2D foundations already available:** immediate-mode widgets, skins and nine-slice backgrounds, groups/scrolling/popups, text wrapping and multiline text, `Camera2D`, texture atlases, source-rectangle/pivot/flip drawing and experimental sprite animation. The `macroquad-tiled` and `macroquad-platformer` companion crates already exist. Extend these paths instead of introducing competing frameworks.
- **Experiment needs:** Coffee Break still owns its movement, menu sizing, rounded-panel drawing and document viewport glue. These motivate the near-term queue; use small public fixtures rather than the experiment's private assets.

## How a round uses this file

The three counter lines above are authoritative: **N** enhancements since the last fixer round, **M** fixer rounds since the last game round, and **D** rounds since the last documentation round. If a counter is missing, recover it from the latest round log here or in the linked history; archived entry counts are not a substitute. Select exactly one round, in this order:

1. If `Next round` is `planning`, rewrite the upcoming queue without changing engine behavior. Leave N and M unchanged, increase D by 1, append a log entry, and set `Next round` back to `normal`. Do not request another planning round.
2. Otherwise if **D is at least 10**, run a **documentation** round. No features or behavior changes. Update rustdoc with short examples for new public APIs, the relevant guides and `examples/README.md`. Maintain `docs/3d-guide.md` and `docs/blender-to-macroquad.md`; introduce focused UI/2D guides as those APIs land. `cargo doc` must build without new warnings and doctests must pass. Set D to 0, preserve N and M, and append a log entry.
3. Otherwise if **M is 2**, run a **game** round. On the VM only, build a small playable 3D, 2D or mixed game using the public API. Choose a recently improved track and exercise menus/HUD/input as well as gameplay. Do not commit this exploratory game, its assets or engine changes; only this roadmap is committed. Record concrete pain points, promote the most important into Priorities, set M to 0, increase D by 1 and leave N unchanged.
4. Otherwise if **N is 5**, run a **fixer** round. Review work since the previous fixer, correcting bugs, documentation gaps, missing tests and API inconsistencies without adding features. Set N to 0, increase M and D by 1, and append a log entry. Review linked history when the previous fixer predates this file's log.
5. Otherwise run an **enhancement** round: implement only the first unchecked priority, tick it, append a dated log entry, increase N and D by 1, and leave M unchanged. Each checkbox must fit one reviewable commit; leave later items alone.

A user-requested roadmap cleanup outside this cycle does not consume a round or change counters. Record it as maintenance. Preserve completed entries and evidence when archiving; never reset the cycle as part of cleanup.

### Implementation and validation rules

- Preserve existing public APIs and struct-literal compatibility. Prefer additive helpers and opt-in behavior. Add no dependencies to the default feature set; the existing optional `gltf` dependency stays behind its feature.
- Pure shapes/queries belong in `macroquad::math` and the prelude; GPU/window operations stay beside drawing/camera code. Extend `macroquad::ui` and the existing 2D/experimental modules before creating alternatives. Keep companion-crate features in their crates.
- Define coordinate spaces explicitly: logical window pixels, physical framebuffer/target pixels, camera world coordinates and sprite source pixels. Reuse the supported input/DPI APIs. Camera up axes remain caller-defined.
- Verify engine rounds on the VM with `cargo build`, `cargo test`, `cargo clippy`, and `cargo build --example <name>` for each new example, including affected optional features. Use headless tests for pure logic and small native/WebGL fixtures for rendering/input changes. State untested platforms and distinguish upload/allocation counts from measured performance. No new CI or GitHub Actions. Push round commits straight to `master`; never force-push.
- Keep test/example assets small, original and self-contained. Exploratory game-round assets and Coffee Break sources/assets stay outside this fork. Check queued resource lifetime, alpha compositing and state restoration when touching UI or 2D rendering.
- A documentation-only maintenance edit needs link, queue, counter and diff checks; it does not require rebuilding or deploying the game.

## Priorities

Read top to bottom across all tracks. Track headings group work; they do not create independent queues. UI and 2D work follows the controller/step pair and precedes the remaining general physics work.

### 1. Finish character movement

- [x] **Character controller** — kinematic AABB body using the completed body sweeps, caller-supplied velocity, normal-based sliding, ground snapping, `on_ground`, ground normal and slope limit. Body size stays in the caller; exclude triggers from solid response. Verify floor strafing, thin-wall blocking, jumping/falling and ceiling contacts with synthetic fixtures. Rigid-body impulses are not prerequisites. Capsule players and moving platforms remain later work; stair stepping is the next separate item.
- [ ] **Character step offset** — add configurable step height to the controller, preserving head clearance and slope limits. Verify ascending/descending stairs, a step that is too high, a low ceiling, landing on furniture/rails and walking off a ledge. Use small authored fixtures and expose contact/ground diagnostics that explain a failed step.

### 2. UI building blocks and interaction

- [ ] **Rounded panels** — add a filled rounded-rectangle drawing helper beside the existing shapes, using non-overlapping geometry so translucent panels have no darker seams. Define radius clamping and empty/invalid-size behavior. Coffee Break currently tessellates these panels itself. Verify zero/oversized radii and alpha coverage on native and WebGL. An outline variant and built-in widget styling integration can follow separately.
- [ ] **Scoped clipping for immediate drawing** — expose a supported nested rectangular clip scope for custom panels, images and text, restoring the previous clip on exit. Intersect nested clips, including an empty intersection; keep the built-in UI clipping path compatible. Define logical-window and render-target coordinates, DPI rounding and viewport bounds. Verify clipped document content, disjoint nested clips, and an unclipped HUD afterward; applications should not need `get_internal_gl` to draw a document viewport. Zoom/pan interaction is separate.
- [ ] **Responsive UI layout helpers** — extend the existing row/column/free layout and groups with explicit padding/gaps, available-width sizing and alignment. Keep this to small layout helpers, preserving current widget calls and skins. Reuse text wrapping and scrolling. A synthetic pause/settings menu must keep its controls reachable at 390 x 400 and desktop sizes, with wrapped labels and oversized content; test geometry without a GPU and inspect resized native/browser layouts. No general constraint solver.
- [ ] **Keyboard-operable buttons** — extend the existing editbox focus machinery with opt-in stable button identity, Tab/Shift+Tab traversal, a visible focus style and Enter/Space activation. Preserve pointer behavior and existing button calls. Verify one activation per press, removed/disabled widgets, mixed editbox/button traversal and modal focus containment/restoration. Checkbox/slider navigation, gamepad navigation and platform accessibility bridges are separate follow-ups.

### 3. 2D coordinates, sprites and examples

- [ ] **Camera2D target-coordinate conversion** — add explicit target-aware world/target conversion while preserving the legacy window-space methods. Existing `world_to_screen`/`screen_to_world` use window dimensions even when a render target is selected. Define target size, viewport origin, Y orientation and how a displayed/letterboxed target maps from window input. Test round trips with a differently sized offscreen target, nonzero viewport, camera rotation and 1x/2x DPI; a tiny picking example must hit the drawn sprite after resizing.
- [ ] **Checked sprite-sheet regions** — add a small validated region representation for grid sheets and explicit source rectangles, with caller-chosen pivots and trimmed-frame offsets. Reuse `draw_texture_ex`, texture ownership and atlases; preserve existing `Animation`/`AnimationFrame` literals. Reject zero-sized/out-of-bounds regions and inconsistent trimmed bounds. Verify asymmetric frames, flips and a stable visible anchor with one tiny original sheet. Atlas packing/import formats and per-frame durations are separate extensions.
- [ ] **Deterministic sprite animation timing** — extend the existing experimental animation path with caller-supplied elapsed time, reset/seek and explicit loop/one-shot behavior, retaining `update()` as a convenience. Advance multiple frames after a long tick and retain fractional time; the current implementation advances at most one frame and resets the remainder. Provide checked construction for empty clips and zero frame/FPS values. Verify exact boundaries, pause/resume, large deltas, completion, independent instances and frame regions through the preceding helper. No animation graph or event system.
- [ ] **2D and UI integration example** — add a small maintained public example with an animated sprite, `Camera2D` world picking and a HUD/pause modal using the completed UI helpers. Verify native/WebGL input, keyboard focus, resizing, clipping, pause/resume and queued texture lifetime. Document the flow in focused UI/2D guides and link it from `examples/README.md`. Reuse the preceding tiny fixtures; this is a library example, distinct from uncommitted exploratory game rounds. It adds no engine feature.

### 4. Remaining 3D and physics foundations

- [ ] **Rigid multi-sphere slide** — add a function taking several sphere centers and one delta, returning one shared translation against the same solids and with the same touch/push-out rules as `slide_sphere_solids`. Preserve that function. Two spheres representing Harbor Bell's hull must stop together at a wall, retain their separation and keep tangential movement along a floor. Do not average independent slide results. Yaw/rotation solving is separate.
- [ ] **Marker tags and Blender duplicate names** — recognize `_collider`, `_trigger` and `_spawn` with an optional single `.<digits>` Blender duplicate tail, retaining case sensitivity and extras precedence. Preserve `GltfSpawn`/`GltfCollider` struct literals; expose string `mq_tag` via additive scene metadata and `marker_tag(node) -> Option<&str>`. Test suffix-only `patrol_spawn.001`, a tagged spawn, missing tags and nonmatching names. This resolves the documented Harbor Bell/Cinder Court selection gaps.
- [ ] **Uniform grid** — `UniformGrid` broadphase with cell size, insert spanning `Aabb`s, overlap/ray queries and clear/rebuild. Store caller `u32` indices. Verify cross-cell objects, boundary queries and duplicate suppression. No BVH or mandatory world ownership.
- [ ] **Rigid body** — kinematic/dynamic bodies with position, linear velocity, mass (zero means static), and an AABB/sphere shape enum. `integrate(dt, gravity)` applies gravity, damping and velocity; static bodies stay fixed. Verify basic integration and invalid time/mass policy. Rotation, contacts and islands are separate.
- [ ] **Collision response** — use the preceding bodies and existing contacts for one discrete separation/impulse step, weighted by mass with optional restitution. Static mass zero stays fixed. A separate static-OBB collider input can reuse `Sphere::contact_obb` without changing the body shape enum. Verify resting/separating pairs and dynamic/static impacts. Use the grid where useful; no continuous rigid-body solver or angular response.
- [ ] **glTF room** — a headless Blender Python generator and committed tiny `examples/assets/room.glb`: floor, walls, trigger, spawn and collider empties. Load/draw the room and use the markers through public APIs. Enable `export_extras`, use explicit roles and test duplicate-name behavior from the earlier marker item. Tests/examples must work without Blender installed.
- [ ] **Triangle mesh collider** — triangles with per-triangle or top-level AABBs; closest ray hit plus triangle index, and AABB/sphere overlaps. Verify nearest-hit selection and a small non-axis-aligned fixture. A linear scan is acceptable; no BVH.
- [ ] **Heightfield** — regular row-major heights with scale/origin, height sampling, AABB overlap and ray queries. Define horizontal coordinates in a basis derived from caller-supplied up (`Vec3::Y` only as the default). Verify slopes, grid edges and a non-Y up axis; do not hardcode XZ internally.
- [ ] **Octree** — static AABBs addressed by caller `u32` indices, built once and queried by AABB/ray. Cap depth and test degenerate clusters. This is a static-scene alternative to the uniform grid, not its replacement.
- [ ] **Distance joint** — constrain two rigid-body positions to a rest length with a small position/velocity correction per step. Verify static/dynamic anchors and zero-length cases. No angular joints or full solver stack.

## Shared 3D and Blender conventions

- `glam` is already re-exported through math/the prelude. Small primitives use public fields and `Copy`, with `const fn` where appropriate. Stateful worlds may use their own modules after their pure queries exist.
- AABBs and rays use world coordinates; `Camera3D::up` is caller-defined and its default remains +Z. `draw_cube`/`draw_cube_wires` take center/full size; `Aabb::from_center_size` matches them. `Obb::half_extents` are half size, and `Obb::from_world_matrix` treats matrix scale as full size. `draw_plane` remains an XZ quad with half-extents; `draw_plane_wires` takes full side length. Reuse existing debug draw helpers.
- glTF is Y-up, right-handed and in meters. Blender's exporter converts Z-up to Y-up; do not convert twice. Apply matching `with_up_axis` choices to scene/draw data. Existing separate scene/model loading remains supported; consult the pose/loader guides for shared sidecars.
- Marker roles/shapes come first from node extras (`mq_role`: collider/trigger/spawn; `mq_shape`: box/sphere/capsule), then recognized name suffixes. Blender export must enable `export_extras`. Duplicate suffix tails and tag queries remain pending until their checkbox is complete.
- Marker dimensions come from imported geometry/transforms: an empty box uses full world scale; a mesh box uses vertex bounds, including the size-2 default Blender cube. Use the imported collider and `GltfHierarchyPose::collider_shape` for posed queries rather than reconstructing mesh size from a matrix. Triggers must be excluded from solid response.
- CPU `GltfScene` images and GPU/material sidecars have different map coverage. Preserve the optional feature boundary and avoid claiming all maps are loaded by every API. The [Blender tutorial](docs/blender-to-macroquad.md), [3D guide](docs/3d-guide.md) and rustdoc describe current behavior; the [historical conventions](docs/roadmap-history.md#blender-asset-track) retain the original design detail.

## Deferred scope

Keep full PBR/environment lighting, shadows/refraction, skinning, CUBICSPLINE/blended clips, shader morphing, moving platforms and capsule controllers out of the current small items. UI text shaping/IME/fallback fonts, gamepad navigation, accessibility bridges, retained UI trees, tilemap batching and broader 2D physics need a separate measured need and scoped priority. Existing tiled/platformer support is a starting point, not missing functionality.
