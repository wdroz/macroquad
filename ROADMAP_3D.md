# 3D roadmap

Enhancements since last fixer round: 2
Fixer rounds since last game round: 0
Rounds since last documentation round: 8

Next round: normal

Source of truth for the unattended 3D enhancement bot on this fork. The goal is to make 3D games easier to build with macroquad: collision primitives, raycasting, simple rigid-body physics, collision response, a character controller, and spatial partitioning. A second track loads a Blender scene exported as glTF 2.0 (meshes, materials, textures, node transforms, and collider / trigger / spawn markup) so a level does not have to be rebuilt by hand.

Macroquad stays a thin, beginner-friendly layer over `glam` (already re-exported from `macroquad::math` and the prelude). Primitives are `Copy` structs with public fields, `const fn` where `Rect` is `const`, and no new crate dependencies on the default feature set. The `gltf` crate is allowed behind the `gltf` feature (see the Blender asset track). Do not break existing public APIs. Do not add GitHub Actions or any other CI. Verify on the VM with `cargo build`, `cargo test`, `cargo clippy`, and `cargo build --example <name>` for any new example. Push straight to `master`. Never force-push.

- Math primitives live in `macroquad::math` and show up through `use macroquad::prelude::*`. Types that need the GPU or the window (`draw_*`, camera unprojection) live next to the existing draw/camera code. - Boxes and rays are axis-aligned in **world space**. Debug wireframes are `draw_aabb`, `draw_ray`, `draw_plane_wires`, `draw_triangle_wires`, `draw_obb`, and `draw_capsule_wires`. `draw_sphere` already takes a center and a radius. `draw_plane` stays the XZ quad, and its `size` is a half-extent; `draw_plane_wires` takes the full side length.

## Pain points from game rounds

- [x] **Marble Maze** (`examples/games/marble_maze.rs`): a sphere sitting on a floor already overlaps it, because boundaries are inclusive. Rejecting any move that `overlaps_aabb` or `overlaps_sphere` sticks the marble to the ground. The game tests a radius 0.02 smaller than the drawn marble, chops the move so a thin floor is not skipped, binary-searches one axis at a time, and zeroes that velocity component. The library had no move-and-slide helper. A center that starts inside a box has no push-out direction: `Aabb::closest_point` returns the center. Per-axis blocking also snags on the 45° bumper, because nothing projects the leftover motion onto the face. Resolved by `slide_sphere`. The game still uses its local workaround.
- [x] **Marble Maze**: a rotated wall's imported collider is the mesh's world `Aabb`, which fills the bumper's gap. The game ignored `GltfCollider.shape` for boxes and rebuilt an `Obb` with `Obb::from_world_matrix`. That matches the visual cube only because the Blender cubes were created with `size=1` (vertices at ±0.5), so the node scale is the full size. A default Blender cube is size 2, and the same workaround would be half the mesh. `GltfColliderShape` had no shared overlap test, so each variant was matched by hand. Resolved when `mq_shape` is `box`: a rotated box is an `Obb`, a mesh box uses the vertex bounds, and `overlaps_sphere` / `overlaps_aabb` cover every variant. Marble Maze's cubes still have no `mq_shape`, so they import as mesh AABBs and the game still rebuilds an `Obb` from the node matrix.
- **Marble Maze**: `Camera3D`'s `Default` up axis is +Z, and that default stays. `GltfScene::with_up_axis(Vec3::Z)` and `GltfModel::with_up_axis(Vec3::Z)` map a Y-up file onto it; `Vec3::Y` is a no-op. The game still sets `up: Vec3::Y` and does not call either helper. The level is parsed twice (`GltfScene` for markers, `GltfModel` for meshes). Triggers and the spawn are not drawn; the goal is a `draw_sphere_wires` on the imported sphere, and the spawn point is treated as the marble center with a radius the file does not store. Cinder Court (2026-10-18) still parses the file twice and sets `up: Vec3::Y`. Its trigger and the capsule column are drawn with `draw_sphere_wires` and `draw_capsule_wires` because empties are not in `GltfModel`.
- [x] **Cinder Court** (top-down shooter, Blender `courtyard.glb`, not committed): WASD moves a sphere of radius 0.4, the mouse ray hits the floor plane (`Camera3D::screen_to_ray` plus `Plane::ray_intersect`), and shots are spheres. Three raider meshes chase. Clear them, then overlap `exit_trigger`. A scripted run won in 248 frames at 1/60 s with health still 8. `slide_sphere` ignores the capsule column and the sphere rock. The column is a `Capsule` of radius 0.45 from `(-1.6, 0.45, -2.4)` to `(-1.6, 1.55, -2.4)`. The rock is a `Sphere` of radius 0.5 at `(2.6, 0.5, 1.2)`. A radius-0.4 body that starts 0.35 outside either solid and slides on +X through it finishes on `start + delta` (`blocked_error = 0`). The midpoint gap (horizontal distance minus both radii) is -0.60 for the column and -0.65 for the rock. The game copies each into an AABB before calling `slide_sphere`, so the round column blocks as a square. Do not change `slide_sphere`'s parameter list; a new function can take the extra slices. Resolved by `slide_sphere_solids`. The game was not committed.

```rust
slide_aabbs.push(Aabb::from_points([capsule.a, capsule.b]).unwrap().expanded(capsule.radius));
slide_aabbs.push(Aabb::from_center_size(sphere.center, Vec3::splat(sphere.radius * 2.0)));
let next = slide_sphere(center, radius, delta, &slide_aabbs, &obbs);
```

- **Cinder Court**: triggers have to be left out of the solid list passed to `slide_sphere_solids`. `GltfColliderShape::overlaps_sphere` does not know `GltfCollider::trigger`, and the exit sphere would become a wall.

- [x] **Cinder Court**: the yawed cover imports as an `Obb` (thin half-extent 0.225). `Sphere::sweep_aabb` does not accept it, and there is no sphere–OBB `Contact`. A radius-0.12 shot through the center starts and ends with `overlaps_sphere == false` while `Obb::ray_intersect` hits. A graze shifted by `half_tangent + 0.45 * radius` along the next axis has `ray_intersect == false`, the midpoint overlap true, and both endpoints clear. The game substeps by the shot radius and destroys the shot on `Obb::overlaps_sphere`. A frame that jumps the box still tunnels, and there is no normal to bounce with. Resolved by `Sphere::contact_obb` and `Sphere::sweep_obb`. The normal points out of the box. The center shot and the graze both report a hit, and a touch that slides sideways is not one. The game was not committed.
- **Cinder Court**: raider meshes are baked in world space. `GltfModel::draw` submits every part, and `GltfDrawMesh` keeps no rest matrix. The game skips spawn nodes and clones three parts (1440 vertices) each frame. The spawn yaw is on `scene.nodes[spawn.node].world` (`Quat` about Y for the player's 40° empty), not on `GltfSpawn`, which is only `node`, `name`, and `position`. Adding `pos - origin` does not apply that yaw. `mq_tag` is in the glTF extras (`"raider"`, `"player"`) and is not stored on the scene. The player radius is the literal `0.4`. A raider's radius is half the longest side of its mesh positions transformed by `node.world`, because a spawn ignores `mq_shape` and stores no size.

```rust
for vertex in &mut mesh.vertices {
    vertex.position += raider.pos - raider.origin;
}
draw_mesh(&mesh);
```

- **Cinder Court**: a suffix-only empty named `patrol_spawn.001` (the name Blender writes when duplicating `patrol_spawn`) is a node and not a spawn. `raider_spawn.001` with extras `mq_role = spawn` does load, but selecting raiders with `name.starts_with("raider_") && name.ends_with("_spawn")` drops it. There is no tag to query instead.

## Blender asset track

Someone builds a scene in Blender (by hand or through an AI-driven Blender MCP server), exports glTF 2.0 (`.glb` or `.gltf`), and a game loads meshes, materials, textures, and the node hierarchy. Colliders, triggers, and spawn points are marked in Blender and become this library's shapes.

The checkboxes live in **Priorities**, interleaved with the collision items they depend on. This section is the convention those items share. Do not implement from this section ahead of the first unchecked priority.

- Cargo feature `gltf` (not a default feature) depends on the `gltf` crate. Parsing bytes must not open a window. Types that need the GPU (`Mesh`, `Texture2D`) stay next to the existing draw code and are their own item.
- glTF is Y-up, right-handed, meters. Blender is Z-up; Blender's glTF exporter converts Z-up to Y-up on export. The loader stores glTF axes as written and does not apply a second conversion. `GltfScene::with_up_axis` rotates a loaded scene so glTF +Y points along a caller-chosen up axis, and `GltfModel::with_up_axis` rotates the baked draw mesh by that same rotation. `Vec3::Y` is a no-op. The model is still a separate parse: call both with the same axis. Macroquad does not assume an up axis (`Camera3D::up` is caller-defined; its `Default` is +Z). Examples in this repo use Y-up, which matches an exported glTF file.
- Node world transforms are the glTF hierarchy (translation, rotation, scale).
- Markup, preferred source first:
  - glTF node `extras`: `mq_shape` = `box` | `sphere` | `capsule`, `mq_role` = `collider` | `trigger` | `spawn`.
  - Otherwise a name suffix: `_collider`, `_trigger`, `_spawn`.
- A `box` on an empty uses the world-matrix translation as the center (not the local translation) and the node's full scale as the size, matching `draw_cube` / `Aabb::from_center_size`. Scale is the length of each column of the world matrix's upper 3×3, so a parent's scale is included and a mirrored (negative) scale stays a positive size. A world rotation that keeps the faces on the world axes, including a quarter turn, stays an `Aabb` whose size lies on those world axes. Any other rotation is an `Obb` from `Obb::from_world_matrix` (a negative scale stays a positive extent and the box stays centered). A mesh with `mq_shape` = `box` uses the transformed mesh bounds instead of the node scale alone, so a default Blender cube (vertices at ±1) is not half the mesh. If a non-uniform parent scale and a child rotation shear that matrix, the mesh box keeps the decomposed rotation and grows until those bounds are inside. An empty does not grow. A `sphere` uses the same world center and the largest of those three lengths as the radius. Spawn points use the world translation. A `capsule` is a `Capsule` along the node's world +Y (glTF Y-up): the radius is the larger of the world X and Z column lengths, and the world Y column length is the distance from the center to an endpoint of the inner segment.
- Empties (nodes with no mesh) are the usual markers. A mesh with a suffix and no `mq_shape` becomes an AABB around its transformed positions.
- Base-color images sampled by a loaded primitive are `GltfImage` values on `GltfScene::images`: 8-bit RGBA, row 0 at the top, no `Texture2D`. `GltfPrimitive::base_color_texture` indexes that list, not the file's texture array. Images no loaded primitive samples are omitted. Normal, metallic-roughness, occlusion, and emissive maps are not loaded. An external image URI is an error only when a loaded primitive samples it. `GltfModel` still uploads textures on its own.
- Checked-in bytes live under `examples/assets/`. A Python script headless Blender can run is how to regenerate them. Tests and examples must not require Blender to be installed.

## Priorities

- [x] **AABB** — `Aabb` in `macroquad::math`: min/max corners, `from_center_size` (same center and full size as `draw_cube`), `from_points`, containment, overlap, intersection, union, closest point, expand/normalize, and a slab `ray_intersect` returning `RayHit` (`t`, `point`, outward `normal`). Inclusive boundaries, same as `Rect`.
- [x] **Sphere** — `Sphere` in `macroquad::math` (center + radius, mirroring `Circle`). `contains`, overlaps sphere, overlaps `Aabb`, closest point, `ray_intersect` → `RayHit`. No solver and no new ray type yet.
- [x] **Ray** — `Ray` { origin, direction } with `point_at(t)`, normalization helper, and closest-hit queries against a slice of `Aabb` and a slice of `Sphere`, reusing `RayHit`. Reject `t < 0`. Do not unproject from the camera in this item.
- [x] **Plane** — `Plane` from unit normal + signed distance, and from three points. Signed distance, which-side test, closest point, `ray_intersect` → `RayHit`, and segment intersection (endpoints on opposite sides).
- [x] **glTF scene** — feature `gltf`. Parse `.glb` / `.gltf` bytes into a `GltfScene`: nodes (name, parent, local translation / rotation / scale, world `Mat4`) and meshes (positions, indices, uvs, normals, per-primitive base-color factor). No images, no GPU, no colliders. Ship a tiny checked-in file under `examples/assets/` and unit-test the hierarchy against it. Axes as in the Blender asset track.
- [x] **Triangle** — `Triangle` { a, b, c }. Barycentric `contains`, plane of the triangle, AABB via `Aabb::from_points`, closest point, and Möller–Trumbore `ray_intersect` → `RayHit` (both winding orders count; `ray_intersect_cull_backface` drops hits that travel with the winding normal). `Ray::closest_triangle` matches `closest_aabb` / `closest_sphere` / `closest_plane`.
- [x] **glTF markers** — read `extras` and name suffixes (see the Blender asset track) into colliders (`Aabb`, `Sphere`), triggers (same shapes, flagged), and spawn points (world position + name). Centers and sizes come from the world matrix, as the Blender track describes. Ignore `capsule`, and do not emit an `Obb` for a rotated box in this item. Turn on the `gltf` crate's `extras` feature in that change (`extras = ["gltf-json/extras"]`). Without it `Node::extras()` is an empty `Void` and the JSON is dropped at parse time. `names` is already on. Extend the sample asset with one box collider empty and one spawn. Unit-test without a window.
- [x] **glTF draw** — `macroquad::gltf_draw::GltfModel` loads embedded GLB images and converts CPU `GltfScene` primitives to `Mesh` chunks. Applies node world matrices, inverse-transpose normals, mirrored winding correction, and triangle-safe `u32` to `u16` remapping with configurable vertex/index capacities. Generates missing normals. Vertex colors hold clamped base-color factors at byte precision; exact factors remain in `GltfSurface`. Supports PNG/JPEG/WebP, material-selected UV sets and `KHR_texture_transform` without flipping V, sampler wrap/magnification settings, names/paths and bounds. `model.draw()` uses the current camera/material; `parts` expose alpha, sidedness, emissive, metallic, roughness, unlit and transmission metadata for an application renderer. No PBR, refraction, alpha sorting, skins, animations or morph targets are built in. GPU texture creation requires an active macroquad context; embedded GLB images only. Example `gltf_textured` and generated checkerboard fixture. The separate CPU-only glTF materials item remains pending.
- [x] **OBB** — `Obb` { center, half_extents, rotation: `Quat` }. `overlaps` AABB (separating axis), overlaps sphere, `contains` point, `ray_intersect` by transforming the ray into box space and delegating to `Aabb`. World-matrix helper (`Mat4`) so a rotated `draw_cube` can share the same pose later.
- [x] **Capsule** — `Capsule` { a, b, radius } as a segment swept by a radius. `contains`, overlaps sphere, overlaps `Aabb`, overlaps capsule, closest point, `ray_intersect` → `RayHit`. This is the body shape the character controller will use.
- [x] **Sphere slide** — `slide_sphere(center, radius, delta, aabbs: &[Aabb], obbs: &[Obb]) -> Vec3` in `macroquad::math`. Move the sphere by `delta`, stop at a surface, and keep the leftover motion projected onto that face so a wall does not cancel the tangent. A sphere that starts merely touching a shape (distance equal to the radius; boundaries are inclusive) must still move along it. Do not make the caller shrink the radius. A center that starts inside a box is pushed out along the shortest axis first. No gravity, no rigid body, no window. Unit-test a sphere resting on a floor that strafes, a sphere that hits an axis-aligned wall and keeps its tangent speed, and a sphere that slides along a yawed `Obb` instead of sticking. Marble Maze hand-rolls a skin and a per-axis search for this.
- [x] **glTF collider shapes** — honor `mq_shape = capsule` as a `Capsule`, and a `box` whose node rotation is not axis-aligned as an `Obb`. Axis-aligned boxes stay `Aabb`. Empties keep using the world-matrix scale as the full size. A mesh marked as a box is the transformed mesh, not the matrix scale alone: a default Blender cube is size 2 (vertices at ±1), so treating its node scale as the full size makes an `Obb` half as big as the mesh. Marble Maze used size-1 cubes and rebuilt every box with `Obb::from_world_matrix` because the imported `Aabb` of the rotated bumper blocked the gap. Document the rule and test one rotated box plus one capsule empty. Give `GltfColliderShape` an overlap test against a `Sphere` and an `Aabb` so a game does not match every variant by hand.
- [x] **glTF up-axis** — reorient a `GltfScene` so glTF +Y maps onto a caller-supplied up axis (`Vec3`). `Vec3::Y` is a no-op, which is the Blender-exporter case. Test that a Z-up result maps glTF Y onto Z and that markers move with the meshes. Do not change the default loader. `Camera3D`'s `Default` up is +Z; leave that default alone (changing it would break existing cameras) and mention it next to this helper.
- [x] **Contact** — `Contact` { normal, penetration, point } for overlapping pairs only: AABB–AABB, sphere–sphere, sphere–AABB, capsule–sphere, capsule–AABB. Normal points from the second shape toward the first (or document the opposite and test it). A pair that only touches (inclusive boundary, penetration 0) still returns that normal, so a sphere sitting on a floor is not "no contact". No impulses and no position correction yet. Return `None` when the shapes are separated.
- [x] **Sweep** — continuous query: moving AABB vs static AABB, and moving sphere vs static AABB, along a delta. Return time of impact in `0..=1` plus the hit normal, or `None` if the path misses. A start that is only touching (penetration about 0, inclusive boundary) and a delta that does not move further into the solid is not an impact; otherwise a sphere resting on a floor cannot sweep sideways. A start that is clearly inside reports `t = 0`. Needed before the character controller.
- [x] **glTF model up-axis** — reorient `GltfModel` with the same rule as `GltfScene::with_up_axis`, so a drawn mesh and the scene's colliders, triggers, and spawns share one up axis. `Vec3::Y` stays a no-op. Marble Maze parses the file twice and sets `Camera3D` `up: Vec3::Y` because the model ignores the scene helper. Do not change `Camera3D`'s default up.
- [x] **Picking ray** — `Camera3D::screen_to_ray` unprojects a screen point (typically the mouse) into a world `Ray` using the same view-projection as `matrix`. The point is top-left, y down. A viewport is the GL viewport converted like `Camera2D::world_to_screen`. The framebuffer is the render target when one is set, otherwise the window. A perspective ray starts at `position`; an orthographic ray starts on the near plane. Direction is unit length. Without a window, a viewport is enough (`aspect` overrides that viewport's size). Unit-tested with a synthetic perspective camera aimed down an axis.
- [x] **glTF materials** — embedded images on the scene as raw RGBA (`width`, `height`, `pixels`) plus the texture index each primitive uses. No `Texture2D` in the pure type. Extend the sample with a 1×1 image and test the bytes.
- [x] **Frustum** — extract six planes from a `Camera3D` view-projection matrix. `contains` / `intersects` tests for a point, a `Sphere`, and an `Aabb` (the AABB test may be conservative). Used for culling, not for collision response.
- [x] **Debug draw** — `draw_aabb` (`draw_cube_wires` with the box center and full size), `draw_ray` (segment to `t`), `draw_plane_wires` (wire square on a `Plane`; `size` is the full side and `center` is projected onto the plane), `draw_triangle_wires`, `draw_obb`, and `draw_capsule_wires` (sphere wires at the inner ends plus four hull lines). `draw_sphere` already existed. The existing `draw_plane` stays the XZ quad, whose `size` is a half-extent, so the new helper could not take that name. A negative `Obb` half extent draws nothing, matching the queries; a zero quaternion is drawn as identity. No new shaders. `examples/aabb_overlap.rs`, `obb_overlap.rs`, and `capsule_overlap.rs` call these instead of local copies. Example `examples/debug_draw.rs`.
- [x] **Sphere sweep against an OBB** — `Sphere::contact_obb` and `Sphere::sweep_obb` in `macroquad::math`. Contact matches the other pairs: the normal points from the box toward the sphere, penetration is `0` when they only touch, and separated shapes return `None`. Sweep matches `Sphere::sweep_aabb`: `SweepHit` with `t` in `0..=1`, the normal out of the box, a touch that does not move further in is not a hit, and a start clearly inside is `t = 0`. Cinder Court's cover is this shape (thin half-extent 0.225). A radius-0.12 move that starts and ends clear of the box has no sweep today, and a graze misses `Obb::ray_intersect` while the midpoint overlaps. Do not change `sweep_aabb`. Unit-test the center shot, the graze, a resting touch that slides sideways, and a start inside the box.
- [x] **Slide against sphere and capsule** — new `slide_sphere_solids(center, radius, delta, aabbs, obbs, spheres, capsules) -> Vec3`. Leave `slide_sphere` with its current arguments. Same rules as that function: a mere touch still slides, a center that starts inside is pushed out along the shortest axis before the move, and the leftover tangent is kept. Cinder Court walked a radius-0.4 body through a capsule column (midpoint gap -0.60) and a sphere rock (midpoint gap -0.65); the game substituted AABBs and the column became a square. Unit-test a strafe past a touching sphere, a capsule column that stops a horizontal move, and the floor strafe still passing through `slide_sphere`.
- [ ] **Draw a moved glTF part** — store on `GltfDrawMesh` the node world matrix that baked its vertices, and add a draw that replaces that matrix (translation and rotation). `GltfModel::draw` still draws every part at the baked pose. Cinder Court clones 1440 vertices a frame to add `pos - origin` and cannot apply the spawn yaw, which lives on `GltfNode::world` rather than `GltfSpawn`. Keep the vertex rewrite pure so a unit test does not need a window; submitting the mesh still needs the GPU context.
- [ ] **Marker tags and Blender duplicate names** — a node named `patrol_spawn.001` is not a spawn, and a string extra `mq_tag` is dropped. Treat a name as a suffix marker when it ends with `_collider`, `_trigger`, or `_spawn`, optionally followed by one Blender duplicate tail `.<digits>` (`patrol_spawn.001` matches, `Player_Spawn` still does not). Extras still win over the suffix for the role. Do not add a field to `GltfSpawn` or `GltfCollider` (public struct literals would break). Store the tag on the scene and return it from `GltfScene::marker_tag(node: usize) -> Option<&str>`, `None` when the extra is absent. Unit-test a suffix-only `.001` spawn and a tagged spawn.
- [ ] **Uniform grid** — `UniformGrid` broadphase: cell size, insert `Aabb` (objects may span cells), query overlap against an `Aabb` or a `Ray`, clear/rebuild. Store caller indices (`u32`), not closures or trait objects, so the API stays beginner-friendly. No BVH in this item. Cinder Court's courtyard was small enough that a nested loop was fine; this stays behind the shape queries the shooter actually missed.
- [ ] **Rigid body** — kinematic/dynamic `RigidBody` with position, linear velocity, mass (zero = static), and a shape enum of AABB or sphere. `integrate(dt, gravity)` applies gravity, damping, and velocity. No rotation, no contacts, no islands.
- [ ] **Collision response** — one discrete step: detect overlaps between rigid bodies (use the grid when it helps, a nested loop is fine at this size), build `Contact`s, separate positions by mass, and apply an impulse along the contact normal with optional restitution. Static mass (`0`) does not move. A dynamic sphere against a rotated static box uses `Sphere::contact_obb` from the sweep item. Leave continuous sweep for the character controller.
- [ ] **Character controller** — kinematic capsule or AABB body. Move with a caller-supplied velocity and collide against static AABBs, OBBs, spheres, and capsules (every solid `GltfColliderShape` can be) using the sweep and slide items above. Snap to ground, and expose `on_ground`, ground normal, and a slope limit in degrees. A spawn is only a position; the body size stays in the caller. Step offset is in this item; moving platforms are not.
- [ ] **glTF room** — a Python script a headless Blender can run that builds a room (floor, walls, a trigger, a spawn, a couple of collider empties) and exports `examples/assets/room.glb`. Commit the bytes so Blender is not required later. Example loads the room, draws it, and uses the imported markers. The script should look like the calls an AI Blender MCP server would make. Mark roles with extras, not a suffix alone, until the duplicate-name item lands: Blender renames a copy to `name.001`, and that suffix-only node is dropped.
- [ ] **Triangle mesh collider** — a list of `Triangle`s plus a bounding `Aabb` per triangle (or a tiny top-level AABB). `ray_intersect` returns the closest `RayHit` and triangle index. Overlap vs `Aabb` and `Sphere`. Linear scan is acceptable; do not build a BVH here.
- [ ] **Heightfield** — regular grid of heights (row-major `Vec<f32>`, scale, origin). Sample height at `(x, z)`, `Aabb` overlap, and `ray_intersect`. Axis of "up" is a parameter (`Vec3`), defaulting to `Vec3::Y` only as a default value, not a hardcoded assumption inside the math.
- [ ] **Octree** — static octree of AABBs addressed by `u32` indices, built once, queried by AABB overlap and by ray. Fixed depth cap so a degenerate cluster cannot recurse forever. This does not replace `UniformGrid`; it is the static-scene alternative.
- [ ] **Distance joint** — constraint between two `RigidBody` positions: rest length, Baumgarte or a single position/velocity correction per step. No angular joints, no full solver stack.
